## Задача
Верни цвет моих баблов в чате к исходному виду — тому, что был до последнего
изменения. Исходные значения есть в твоей git-истории. Сделай как положено
(с коммитом) и добейся, чтобы я снова видел прежний цвет.

## Предусловия (контекст «до»)
- ИСПОЛНЯЕТСЯ ВСЕГДА после 010, даже если 010 = FAIL (это обязательный откат
  и одновременно самостоятельный кейс).
- context.json: `ts_fence`, `before_sha` (git HEAD ДО этого кейса, т.е. уже
  с коммитом из 010), `css_snapshot` — тот же снапшот «до 010» (исходные
  значения, к которым должно вернуться), baseline-цвет DOM из 010.

## Шаги исполнителя
1. `chat.py send` с текстом задачи.
2. `chat.py wait --since <ts_fence> --timeout 900 --settle 60`.
3. Перезагрузить страницу чата, артефакты: `after-revert-ui.png`,
   `computed_style.json` {"baseline": <цвет до 010>, "current": <сейчас>}.

## Верификация
Программная: обе CSS-переменные равны исходному снапшоту; цвет в DOM
вернулся к baseline до 010; style.css чист в git (изменение закоммичено,
а не брошено в рабочем дереве).
Vision (2 судьи, рубрика + before-ui.png из 010 + after-revert-ui.png):
1. Цвет баблов на after-revert совпадает с before (из кейса 010).
2. UI живой и нормально отрендерен.

## Откат
ВСЕГДА после 011 (даже при PASS): оркестратор сверяет, что ВСЕ файлы,
тронутые парой 010+011, вернулись к состоянию ДО кейса 010. Агент в happy-path
обычно ревертит только style.css — побочные файлы 010 иначе останутся в живом
репо навсегда. Остаточная очистка:
1. `git -C repo checkout <before_sha 010> -- .` — восстановит рабочее дерево и
   индекс для всех путей из <before_sha> (modified/deleted/typechange, один вызов).
2. Удалить появившиеся после <before_sha> пути (сравнение с индексом — из
   него строится компенсационный коммит):
   `git -C repo diff --cached --no-renames --diff-filter=A --name-only <before_sha 010>`
   → каждый `git -C repo rm -f --ignore-unmatch`.
3. Untracked вне qa/ — в отчёт, не удалять вслепую.
4. Закоммитить от QA-автора; убедиться, что `git diff <before_sha 010> HEAD`
   пуст И `git status --porcelain` чист.
Если очистка потребовалась — пометить «остаточная очистка: <файлы>»; полный
несостоявшийся откат цвета — FAIL кейса. Полный алгоритм — в разделе
«ОБЯЗАТЕЛЬНАЯ СВЕРКА ПОСЛЕ 011» оркестратора (SKILL.md).
